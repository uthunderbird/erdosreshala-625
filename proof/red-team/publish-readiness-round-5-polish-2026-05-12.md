# Publish-Readiness Round 5 (final): Reader Experience & Polish

**Target.** The entire `publish/erdos-625/` package:
`README.md`, `ROADMAP.md`, `DEVELOPMENT.md`, `proof/proof.md`,
`paper/main.tex`, `paper/SOURCES.md`, `Erdos625/README.md`,
`Erdos625/extras/README.md`, `proof/AXIOM_SNAPSHOT.txt`,
`proof/red-team/README.md`, `proof/methodology/README.md`,
plus a sweep over `proof/red-team/*.md`, `paper/red-team-*.md`,
and `proof/methodology/operator-{profile.yaml,harnesses/*.txt}`.

**Round.** 5 of 5 (final). Focus: **reader experience & polish — the
last 5%.** Rounds 1–4 (honesty, provenance, navigation, math rigor)
are explicitly out of scope and not re-litigated.

**Mechanism claim under audit.** "The package reads as a polished,
single-authored release-ready submission despite its multi-session
iterative provenance."

**Verdict (preview).** Substantially true for ~85% of the package
surface. Breaks down at: (i) the README disclosure front-loading
above the substantive claim; (ii) two `release-time` placeholders
embedded in body prose of the paper abstract and the README; (iii)
a small number of phrase-level artefacts (historical-novelty
overclaim, "pending peer review" status lines, residual `TODO` /
Cyrillic, defensive footnotes from earlier-round repairs); (iv) a
companion paper that, at ~3,800 words / ~8–10 typeset pages, is
*shorter* than arXiv-math.PR conventional length for a result of
this scope. The fix set is small and structural.

---

## Method

Critique-first, evidence-grounded. Every finding below carries a
`file:line` reference and an exact-quote snippet. Findings are
classified P0 / P1 / P2 from a *polish* lens:

- **P0** — anything still wrong from a polish lens: confidence
  miscalibration, factual remnants of earlier states, broken
  reader-flow at first-impression touch-points.
- **P1** — rough edges that detract from reader experience but
  are not visibly broken.
- **P2** — subjective taste calls.

Findings are NOT classified by mathematical severity — that was
round 4. A P0 here is a *polish* P0.

Evidence sweep performed:
- read of all 11 target files plus operator-profile.yaml;
- grep across the package for `TODO|FIXME|TBD|XXX|HACK|[release-time]|placeholder`;
- grep for hedging phrases (`we believe`, `we hope`, `appears to`,
  `peer.review`, `to our knowledge`, `first published`);
- grep for Cyrillic (`[\x{0400}-\x{04FF}]`);
- grep for round-N references that leak into user-facing prose;
- code-fence-language audit (` ``` ` vs ` ```lean ` vs ` ```bash `);
- trailing-whitespace and multi-blank-line audit;
- voice-pronoun ratio (`we` vs `this work` vs passive) across
  README and `paper/main.tex`;
- filename-convention survey of `proof/red-team/`, `paper/`,
  `proof/red-team/legacy/`.

## P0 findings (polish lens)

### P0-1 — README disclosure front-loading buries the substantive claim

**File:** `README.md`, lines 18–79.

**Evidence.** Layout of the first 80 lines:

| Lines | Content | Words (approx) |
|---|---|---|
| 1–7 | Title + one-sentence claim | ~50 |
| 8–16 | Quick links | ~50 |
| 18–34 | Provenance blockquote (LLM pipeline, codex-brain, 1M-context) | ~210 |
| 36–52 | Limitation-framing blockquote (shared-blind-spot) | ~180 |
| 54–57 | Reject-ratio blockquote | ~45 |
| 59–64 | Human-supervisor blockquote (includes a release-time placeholder) | ~55 |
| 66–68 | Anthropic non-endorsement blockquote | ~30 |
| 70–79 | Prize-disclaimer blockquote | ~100 |
| 81 | First substantive line: `**Proof status**: complete on the in-probability form.` | — |

The visitor encounters **≈620 words / ≈62 lines of disclosure
blockquotes** between the one-sentence claim and the first
substantive content. The disclosure stack is single-tier (no
headline → at-a-glance → detail layering). The round-5 brief
focus (c) is explicit: "are they layered intelligently (most
important first, more detail on click-through), or do they
front-load multiple paragraphs of caveats before the actual claim,
making the visitor zone out?" — the package front-loads.

Exact quote at the worst point, line 18:
```
> **Provenance (read first).** This formalization — the Lean source, the
> companion paper, the proof writeup, and the five red-team audit passes
> in `proof/red-team/` — was generated by an LLM-agent pipeline ...
```

**Why this is a polish P0, not a P1.** The brief's
first-impression-diagnostics (e) explicitly requests three thought
experiments. All three fail at the README first-impression layer:

- *Random visitor, first 200 words.* Sees title, claim, quick
  links, and opens the Provenance blockquote. Has NOT yet seen
  the four-theorems table, the high-level proof idea, the
  build/verify instructions, or the axiom inventory.
- *Skeptical mathematician, abstract + Thm 1 + §6.* Passes for
  `paper/main.tex` (abstract is technical, Theorem 1 is on
  page 2, axiom §6 follows §5 — the layering works). README
  fails the analogous test.
- *AI-skeptic journalist screenshot.* The screenshot of the
  README header captures the title, one-sentence claim, and
  the opening of `> **Provenance (read first).** ... codex-brain
  adapter ran gpt-5.3-codex-spark at effort=low`. The
  pull-quote `effort=low` reads as a self-own out of context
  (in context it is the orchestrator's action-selection
  inference budget, not the proof-author inference budget; the
  context is in the parenthetical that the screenshot will not
  capture).

**Repair shape (not in this round).** Three-tier layering on
`README.md`:
- *Tier 1, headline:* title + one-sentence claim + one-line
  at-a-glance disclosure (e.g., "LLM-agent generated under human
  supervision; Lean-kernel-verified modulo 4 paper-axioms + 3
  kernel-axioms; not a \$100-prize claim. Full disclosures
  follow the substantive sections.").
- *Tier 2, substance:* "Proof status", "Flagship theorem", "Four
  theorems", "Axiom inventory", "High-level proof idea",
  "Building and verifying", "Repository layout".
- *Tier 3, full disclosures:* the five existing blockquotes,
  unchanged in content, placed after the substantive sections
  and before "References" / "License". Content is preserved;
  only ordering changes.

### P0-2 — Two `release-time` placeholders are embedded in body prose

**Files / lines:**

(a) `paper/main.tex`, lines 96–99:
```
The complete
Lean development is available at
\url{https://github.com/uthunderbird/erdosreshala-625} (release-time
note: this URL is the intended public target; if the release ships
under a different repository name, update both this line and the
Acknowledgments before posting to arXiv).
```
This is the **final sentence of the abstract**, in body prose,
with the `release-time note: ...` parenthetical visible to any
reader. arXiv abstracts do not ship with self-addressed action
items embedded in them; this is a single-authored-release seam.

(b) `README.md`, lines 59–64:
```
> **Human supervisor.** Daniyar Supiyev directed the proof strategy
> at the branch-point level. Contact: GitHub issues at the repository
> (URL to be inserted at release time; the target repo is
> `https://github.com/uthunderbird/erdosreshala-625` and the
> placeholder in `paper/main.tex` will be replaced at release time).
> No institutional affiliation is claimed.
```
Two `release time` markers in a single blockquote. The target
URL is already named (and is the same in both files), so this
should not require deferred substitution at all — the URL can be
inlined once and the placeholder language removed.

The round-5 brief (g) explicitly flags this category:
"Any remaining placeholder text — e.g. `[release-time]`, `TBD`,
`TODO` — should be either resolved or explicitly flagged in
ROADMAP as a known release-time action." Neither is currently
done; they sit in body prose.

**Why P0, not P1.** Both placeholders are at first-impression
locations (paper abstract; README provenance blockquote). A
visitor screenshotting the abstract will capture the placeholder.
A mathematician evaluating the paper's release-readiness will
see the placeholder before the Acknowledgments.

### P1-11 — Paper word count is *short*, not long, for the result claimed

`paper/main.tex`: 730 LaTeX lines, ~3,800 words. The
round-5 brief assumed 15–25 pages would be the conventional
range and asked whether the package "matches arXiv length
conventions." The actual measurement: at 11pt single column with
1.1in margins, 3,800 words typesets to roughly **8–10 pages**.
That is *below* arXiv math.PR convention for a "main result +
axiomatized chain" paper, which typically lands in the 12–20
page range.

This is **not a defect** per se — short papers are fine — but
for a round-5 polish review it is worth naming because:
- a reader expecting a full development may treat the paper as a
  "research note" or "announcement";
- the package's README presents this as a complete release, and
  a complete release would conventionally include a longer
  discussion section (extended comparison to Heckel-Riordan,
  the slack-constants regime, the deep-crossing margin
  numerical verification, the sharp-rate gap, the axiom-fitness
  defense) inline in the paper rather than scattered across
  audit notes.

Working criticism, not verified issue: the package is consistent
(everything is *somewhere*); the paper just elects to be terse.
Bounded concern, P1: this is a length-vs-substance signal worth
flagging.

## Mechanism Audit

**Claim under audit.** "The package reads as a polished,
single-authored release-ready submission despite its
multi-session iterative provenance."

**What is promised (implicit).** A single coherent release
artefact — README → roadmap → proof → paper → audit trail —
without visible repair-seams from multi-session development.

**What the package delivers.** Substantial polish on:
- Filename convention (uniform across `proof/red-team/`, `paper/`,
  `proof/red-team/legacy/`; one cosmetic outlier).
- Whitespace hygiene (zero trailing-whitespace lines, zero
  multi-blank-line runs across all eight target markdown files).
- Cross-file fact consistency (four theorems, axiom inventory,
  prize-disclaimer wording, the five-red-team-pass mapping all
  match across README / ROADMAP / proof.md / paper/main.tex /
  paper/SOURCES.md).
- Heading-case discipline (level-1 Title Case, level-2 sentence
  case, with one tolerable math-leading heading at
  `Erdos625/README.md:63`).
- Per-artefact provenance footers in `proof/red-team/` (round-2
  P1-7 repair).
- Filename-convention discoverability via `proof/red-team/README.md`
  chronological index and the "five passes" mapping.

**Where it falls short.**
- README disclosure front-loading (P0-1): ~62 lines of
  disclosure-blockquote precedes "Proof status" line 81.
- Two `release-time` placeholders embedded in body prose at
  first-impression locations (P0-2: `paper/main.tex` abstract,
  README provenance blockquote).
- "To our knowledge, the first published …" historical-novelty
  overclaim (P1-1).
- Two "pending peer review" status lines implying a review
  process not in motion (P1-2).
- Literal `TODO` marker in author-added comment
  (`operator-profile.yaml:22`, P1-7).
- Cyrillic criterion quote embedded mid-English-prose in a
  red-team report (P1-8).
- Two defensive footnotes from prior repair rounds (P1-4, P1-5)
  and one corollary status-flag stutter (P1-6).
- `paper/main.tex` self-commentary preamble comment (P1-3).
- Empty `Erdos625/extras/` placeholder README (P1-10).
- Short paper (~3,800 words / ~8–10 pages) for the result
  claimed (P1-11; bounded concern).

**Minimal fix set.**
- *P0 — required for the "release-ready single-authored" reading:*
  - P0-1: re-layer README into three tiers (headline / substance /
    disclosures).
  - P0-2: resolve both `release-time` placeholders — either
    inline the final URL once or move all release-time actions to
    a single `ROADMAP.md` "Release-time actions" block.
- *P1 — strengthening fixes:*
  - P1-1: soften the historical-novelty claim in `DEVELOPMENT.md`
    and `paper/main.tex`.
  - P1-2: rephrase the two "pending peer review" status lines.
  - P1-3: drop the LaTeX preamble self-commentary at
    `paper/main.tex:33–34`.
  - P1-4: deduplicate the slack-constants paragraph.
  - P1-5: cut the defensive parenthetical at
    `paper/main.tex:294–298`.
  - P1-6: drop the `[\emph{not in Lean}]` corollary title flag
    (the following prose already says it).
  - P1-7: resolve the `TODO` in `operator-profile.yaml:22`.
  - P1-8: translate / footnote-translate the Cyrillic criterion
    quote in `erdos-625-full-axiom-check-2026-05-11.md:113–114`.
  - P1-9: smooth the README sentence flow at lines 27–32.
  - P1-10: delete `Erdos625/extras/` directory + README, or fill
    it.
  - P1-11: optional — expand `paper/main.tex` discussion section
    to bring page count into arXiv math.PR conventional range
    (or accept the terse-paper choice and do nothing).
  - P1-12: drop the "read first" / "read second" hints when the
    layering changes — they are reading-order anti-cues.
  - P1-13: cut the inline "mobile-rendering note" at
    `README.md:148–151`.

**Verdict.** Claim is **substantially true** at ~85% of the
package surface and **breaks down** at a small, well-localized
set of phrase-level and ordering-level artefacts. The fix set
is small and structural; no disclosure is removed, no factual
content changes. The repair pass should be tractable in one
session.
