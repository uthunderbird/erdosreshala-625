## ADR-1: Route selection — exact-no-empty profile chain vs. Theorem 1 route

**Date**: 2026-05-05

**Question**: HP-2023 proves a chromatic lower bound via two routes:
- Route A: Theorem 1 (direct first-moment argument; axiomatizes the full Theorem 1 of HP-2023)
- Route B: Lemma 5 + eq:wert + eq:wert2 (exact-no-empty profile reduction; axiomatizes two specific equations)

**Options considered**:
- Route A: simpler to state, but axiomatizes a full theorem — admitting more mathematical content as black-box
- Route B: more detailed; axiomatizes the two specific paper equations that do the real work; the combinatorial reduction connecting those equations to the chromatic lower bound is fully proved in Lean

**Decision**: Route B (exact-no-empty profile chain, implemented in `PartBProfileBridge.lean` and `ChromaticConnection.lean`)

**Rationale**: Route B has a smaller axiom footprint per unit of mathematical content. Axiomatizing Lemma 5 + eq:wert (rather than the full Theorem 1) means more of the proof is verified in Lean and less is admitted. The exact-no-empty chain is fully proved with 0 sorry above the two source lemmas.

## ADR-2: Cochromatic upper bound — Azuma–Hoeffding concentration strategy

**Date**: 2026-04-13 to 2026-04-15

**Question**: How to prove P[ζ(G) ≤ k* − n^{1−ε/2} + 2n^{0.999}] ≥ 1 − ε?

**Options considered**:
- Direct second-moment method (Paley–Zygmund) applied directly to ζ — would need the full second-moment distribution of ζ, which is not available from the paper
- Two-stage approach: Paley–Zygmund for existence (P[Z > 0] > 0 for a specific coloring count Z), then Azuma–Hoeffding for concentration (ζ is 1-Lipschitz under vertex exposure)

**Decision**: Two-stage approach (implemented in `ZetaConcentration.lean` and `BoundedDifferences.lean`)

**Rationale**: The Azuma–Hoeffding concentration infrastructure (BoundedDifferences.lean) is fully proved with 0 sorry — this is the part that produces the high-probability bound from a mere existence statement. The Paley–Zygmund step requires Proposition 5(b) of Heckel 2024, which provides the second-moment bound on Z; this is the single admitted axiom in Part C. The separation cleanly isolates what is verified (concentration) from what is admitted (the second-moment bound).

## ADR-3: Gap arithmetic — proved, not axiomatized

**Date**: 2026-04-30

**Question**: Should the inequality n^{1−ε/2} − n^{1−0.9ε} − 2n^{0.999} ≥ n^{1−ε} (for ε < 0.001 and all large n) be axiomatized or proved?

**Options considered**:
- Axiomatize: treat it as a cited analytic fact, like the paper-backed axioms
- Prove: formalize it directly using Lean's `Real.rpow` machinery

**Decision**: Proved (implemented in `GapArithmetic.lean`, 0 sorry, 0 axioms)

**Rationale**: This is a purely analytic inequality with no probabilistic content. Lean's `norm_num` and `rpow` tactics can handle it. Axiomatizing a provable inequality inflates the axiom count without mathematical justification and removes an opportunity for a fully verified component.

## ADR-4: Axiom naming and citation discipline

**Date**: 2026-05-05 to 2026-05-10

**Question**: How should paper-backed axioms be named and cited in Lean?

**Options considered**:
- Short generic names (e.g., `axiom_hp_1`, `axiom_hp_2`, `axiom_heckel_1`) — easy to read but require cross-referencing to understand what is admitted
- Descriptive content-encoding names (e.g., `paperPartBThresholdAverageClassAsymptoticLowerCriterionTarget_source`) — verbose but self-documenting

**Decision**: Descriptive content-encoding names, with each axiom declaration citing the paper, arXiv ID, theorem/equation number, and a plain-language description

**Rationale**: When a reader runs `#print axioms Problem625.Publishable.erdos_625`, the output is the primary record of what is admitted. Self-documenting names make this output interpretable without cross-referencing. A reader who sees `heckel_cochromatic_second_moment` immediately knows which mathematical claim is admitted; `axiom_hp_1` would require consulting a separate document.

## ADR-6: InMainRange upper bound — Stirling approach abandoned

**Date**: 2026-05-10

**Question**: Can the upper bound `μ(n, thresholdFloor n) ≤ n^{1-ε}` (the second conjunct of `InMainRange ε n`) be proved unconditionally from first principles, thereby eliminating it as a hypothesis of `erdos_625`?

**Approach attempted**: A file `InMainRangeUpper.lean` was created (commit `2d16403`, deleted in the following commit) that:
1. Proved `C(n, k) ≤ (ne/k)^k` via the Stirling lower bound `(k/e)^k ≤ k!` — correct.
2. Proved `μ(n, α) ≤ (ne/α)^α · 2^{-α(α-1)/2}` — correct.
3. Attempted to prove `α·log₂(ne/α) − α(α−1)/2 ≤ (1−ε)·log₂ n` for `α = thresholdFloor n` — **false**.

**Why the key lemma is false**: The Stirling exponent `E(α) = α·log₂(ne/α) − α(α−1)/2` satisfies `E(threshold n) ≈ 0` (by definition of the threshold as the first-moment crossing). Its derivative is `E'(α) ≈ −(log₂n − log₂log₂n)` (large negative) at the threshold. Since `thresholdFloor n = threshold n − δ` for `δ ∈ [0, 1)`, we get `E(thresholdFloor n) ≈ δ·(log₂n − log₂log₂n)`, which can be as large as `log₂n − log₂log₂n`. This exceeds `(1−ε)·log₂n` for all ε > 0 and large enough n. Confirmed numerically: at n = 100, 500, 2000, 10000, the Stirling bound gives `μ_Stirling > n^{1-ε}`.

**Why this reflects a correct mathematical fact**: The upper bound `μ ≤ n^{1-ε}` is NOT universally true for large n. It fails near threshold crossings — the windows of n where `thresholdFloor n` increases. These crossings form an infinite sparse set. `InMainRange` is therefore correctly a hypothesis, not a conclusion: it excludes the threshold-crossing windows where the proof technique does not apply.

**Options considered**:
- Replace the false lemma with an axiom citing HP-2023 — rejected: HP-2023 does not state this bound as a universal eventual fact; doing so would be mathematically dishonest.
- Keep the file as documentation — rejected: the file was not imported anywhere and is not reachable from the build graph; an orphaned file with a false anchor theorem provides no documentation value and creates an integrity risk.
- Delete the file — chosen.

**Decision**: Delete `InMainRangeUpper.lean`. The correct utility lemmas (`choose_le_ne_div_k_pow` and `expectedIndSets_le_stirling_bound`) may be revived in a future file if a legitimate use is found.

**Consequence for the main theorem**: `InMainRange ε n` remains a hypothesis of `erdos_625`. Discharging the upper bound conjunct would require understanding the exact distribution of μ near the threshold — a deeper result, likely requiring the second-moment method or fine-grained threshold analysis, not accessible from the Stirling inequality alone.

## ADR-7: 100%-coverage extension via the $\alpha-2$ crossing branch

**Date**: 2026-05-11

**Question**: How to upgrade `erdos_625_97` (~97% coverage, conditional on
`InMainRangeMod`) to an unconditional 100%-coverage theorem `erdos_625_full`?

**Options considered**:
- **(α-2) case split** (chosen): on $\neg \mathrm{InMainRangeMod}\,\varepsilon\,n$,
  switch from level $\alpha-1$ to $\alpha-2$. By HP-2023 eq:mualpha-2,
  $\mu_{\alpha-2}/\mu_\alpha = \Theta(n^2/\log^2 n)$, so for every crossing $n$,
  $\mu_{\alpha-2}$ stays comfortably inside HP-2023's $[n^{1.1}, n^{2.9}]$
  application range — eliminating the spike obstruction that limited Heckel 2024
  to InMainRange.
- **Wait for Heckel/Panagiotou** to publish the $\alpha-2$ extension natively
  (open work as of 2026-05).
- **Strengthen Heckel 2024 internally** via a different route (e.g. coupling
  arguments). Rejected as out of scope.

**Decision**: Add 3 new paper-backed axioms at level $\alpha-2$
(`partB_alphaMinusTwo_firstMomentBelowOne_source`,
`chi_alphaMinusTwo_lower_bound_whp`, `zeta_alphaMinusTwo_upper_bound_whp`)
and assemble the proof via a case split on `InMainRangeMod`. The three
axioms are paper-backed by HP-2023 Lemma 8.1 and Heckel 2024 Prop 5(b)
(the last one as an $\alpha-1 \to \alpha-2$ extrapolation — disclosed).

**Rationale**: The case-split approach exposes the *exact* boundary between
"published math" and "this repo's contribution" — the boundary is precisely
the three new $\alpha-2$ axioms, which cite HP-2023 Lemma 8.1 (literally
applicable at $a \in \{\alpha-1, \alpha-2\}$) and the symmetric move of
Heckel 2024 Prop 5(b). The structural margin
$\mu_{\alpha-2}/\mu_\alpha = \Theta(n^2/\log^2 n)$ has been numerically
verified for $n \in [100, 10^6]$ and asymptotically via mpmath for
$n \in [10^7, 10^{12}]$ (`proof/red-team/r2b-step1-results-2026-05-11.md`).

## ADR-8: Clean rate `n^{1-2ε}` via `rpow_clean_bound_eventually`

**Date**: 2026-05-11

**Question**: `erdos_625_full` proves the structural bound
$\chi - \zeta \ge n^{1-\varepsilon} - 2n^{0.99}$, which is awkward near the
boundary of validity ($n^{0.99}$ comparable to $n^{1-\varepsilon}$ for small
$n$). Should we tighten to a cleaner expression like $n^{1-2\varepsilon}$?

**Options considered**:
- Add the rpow comparison `rpow_clean_bound_eventually` as a pure
  real-analysis helper lemma and derive `erdos_625_full_clean` (chosen).
- Restate the structural bound as the final result.
- Skip the cleanup; treat it as a referee-time choice.

**Decision**: Add helper lemma `rpow_clean_bound_eventually` (50 lines,
0 axioms; uses Mathlib's `tendsto_rpow_neg_atTop`) proving
$n^{1-2\varepsilon} \le n^{1-\varepsilon} - 2n^{0.99}$ eventually in $n$,
then derive `erdos_625_full_clean` as a one-step corollary of
`erdos_625_full` + the helper. Same axiom set; no new axiom.

**Rationale**: The clean rate is the form referees and readers expect to
see; the structural bound is an implementation detail. The helper lemma
costs ~50 lines and is pure real analysis (no probability), so it does
not bloat the load-bearing chain.

## ADR-10: LLM-agent generation with human-in-the-loop supervision

**Date**: 2026-05-12 (added during round-1 publish-readiness repair)

**Question**: How should the LLM-agent provenance of this development
be disclosed in the published artefact?

**Background**: The entire formalization — Lean source, writeups
(README, ROADMAP, proof.md, paper/main.tex, SOURCES.md), and all five
internal red-team audit passes under `proof/red-team/` — was generated
by an LLM-agent pipeline (Anthropic Claude Opus 4.7,
model id `claude-opus-4-7[1m]`, the 1M-context variant, driven by the
`operator` agent orchestrator at
https://github.com/uthunderbird/vibechord whose codex-brain adapter
ran `gpt-5.3-codex-spark` at `effort=low`) under human-in-the-loop
supervision. The human
supervisor selected the proof strategy at the branch-point level,
accepted or rejected proposed proof steps, ran the Lean build, and
chose which red-team findings to act on. The agents generated and
edited the source. The five `/swarm-red-team` audit passes were
likewise conducted by the same pipeline and are therefore *internal*
adversarial audits, not third-party reviews.

**Options considered**:
- Disclose nothing; present as a conventional human-authored
  formalization. Rejected as dishonest.
- Disclose only in a buried acknowledgments line. Rejected — easy to
  miss, frames provenance as a minor detail rather than a load-bearing
  fact about which correctness signals are independent.
- Disclose prominently in `README.md`, `Erdos625/README.md`,
  `paper/main.tex` Acknowledgments, `ROADMAP.md`, `proof/proof.md`,
  and (this) `DEVELOPMENT.md`. **Chosen.**

**Decision**: Add a visible "Provenance" block above the fold in
`README.md`, a "Provenance and Acknowledgments" section in
`paper/main.tex`, and a top-of-file disclosure in `Erdos625/README.md`,
`ROADMAP.md`, `proof/proof.md`, and `DEVELOPMENT.md`. State explicitly
that (i) proof *generation* (not only audit) was performed by an
LLM-agent pipeline, (ii) the five red-team passes were conducted by
the same pipeline and are therefore not third-party, and (iii) the
Lean kernel is the only third-party correctness signal (it verifies
the proof modulo the seven enumerated axioms).

**Rationale**: A reader assessing the contribution should know which
correctness signal is machine-checked (the Lean kernel verifying
seven axioms) and which is not (the axiom-to-paper correspondence,
the hybrid-axiom disclosures, the writeups, and the audit reports).
The honest framing is also a genuine novelty of the work — this is,
to our knowledge, the first published Lean 4 development of a
sizeable random-graph-theory result produced primarily by an LLM-agent
pipeline. Being explicit about the methodology is both honest and
informative.

**Limitation framing (shared-blind-spot risk).** LLM-generated
proofs may exhibit plausibility-driven failure modes that can survive
same-model internal critique because the proof author and the critic
share training-data blind spots. Here the proof author and the five
internal red-team critics are the same model
(`claude-opus-4-7[1m]`); the internal audits are therefore
structurally incapable of detecting blind spots inherited from
training. The Lean kernel acceptance reduces but does not eliminate
this risk: the four paper-backed axioms remain admitted, and the
natural-language disclosures surrounding them remain LLM-authored.
External verification — by an unrelated reader, a different model,
or a human mathematician — is encouraged. Cross-model auditing was
technically available through the `operator` framework's adapter
layer (see ADR-12 below) but was not used in this development.

## ADR-11: Origin of the four paper-backed axioms (proposal authorship)

**Date**: 2026-05-12 (added during round-2 publish-readiness repair)

**Question**: Who proposed each of the four paper-backed axioms in
the flagship `erdos_625_full_clean` axiom set — the human supervisor
(axiom-as-strategic-citation-boundary) or the LLM agent
(axiom-as-proof-engineering-shortcut)?

**Background**: The four paper-backed axioms are the entire boundary
between "published math + Lean-verified" and "this repository's
contribution". For a reader scoring the contribution, who proposed
each axiom is decision-relevant. The round-1 disclosure
("the human supervisor selected the proof strategy at the
branch-point level") was procedurally honest but ambiguous about
the granularity of axiom proposal.

**Authorship breakdown**:

- **A1 `lemma_7_20_modified`** (HYBRID). *Structurally proposed by
  the LLM agent.* The agent read Heckel 2024 §Discussion, identified
  the explicit conjecture that HP-2023 Lemma 7.20 generalizes to the
  weakened lower bound $\mu_\alpha \ge n^{x_0+\varepsilon}$, and
  proposed the modified axiom together with the in-repository
  numerical certificate `lemma_7_10_ext`. The Python certificate
  script
  (`proof/red-team/num-gap-lemma710-extension-2026-05-10.py`) was
  agent-authored. The human supervisor approved the citation
  boundary at the Heckel-2024-§Discussion level.

- **A2 `partB_alphaMinusTwo_firstMomentBelowOne_source`** (literal).
  *Proposed by the LLM agent*, narrowing a prior wider axiom
  (`KThresholdGapSource`) so that only the first-moment input
  paragraph of HP-2023 Lemma 8.1's proof is admitted. The human
  supervisor approved the narrower citation boundary.

- **A3 `chi_alphaMinusTwo_lower_bound_whp`** (literal). *Proposed by
  the LLM agent* after a main-agent-suggested correction round: an
  initial attempt had a sign / inequality direction error that the
  human supervisor pointed out; the corrected statement was then
  authored by the LLM agent. The human supervisor approved the
  citation boundary at HP-2023 Lemma 8.1 + Markov.

- **A4 `zeta_alphaMinusTwo_upper_bound_whp`** (EXTRAPOLATION).
  *Proposed by the LLM agent*; the $\alpha-1 \to \alpha-2$
  extrapolation framing emerged from a swarm session moderated by
  the human supervisor and was then refined by the LLM agent. The
  decision to admit the extrapolation as an axiom (rather than block
  on a literal $\alpha-2$ peer-reviewed citation) was approved by
  the human supervisor.

**All four axiom statements went through internal swarm and
red-team review before commit.** The human supervisor's
contribution is best characterized as: (i) approving each citation
boundary, (ii) catching the A3 sign error, (iii) running the Lean
build, (iv) selecting which red-team findings to act on, and (v)
deciding scope (e.g., not claiming the \$100 prize).

**Decision**: Record the above authorship breakdown explicitly so
that a reader can weigh, for each of the four load-bearing axioms,
the relative contribution of LLM proposal and human approval. Cross-
link this ADR from `paper/SOURCES.md` per-axiom blocks.

**Rationale**: The opacity of axiom-proposal authorship was a P0
finding of round-2 red-team. Disclosing it eliminates a screenshot-
quotable adversarial reading.

## ADR-12: Reject ratio, HIL granularity, and cross-model auditing

**Date**: 2026-05-12 (added during round-2 publish-readiness repair)

**Publication-package note**: Local agent harness dumps are not shipped
in this package. The reproducibility discussion below records the
operator/orchestration methodology at a high level without publishing
machine-local prompt logs or absolute-path harness files.

**Question**: Three reproducibility-of-process questions left
unanswered by ADR-10 / ADR-11: (i) what was the order-of-magnitude
reject ratio during development? (ii) at what granularity did the
human supervisor review proposed diffs? (iii) was cross-model
auditing — driving a critic of a different model family — attempted
as a partial mitigation of the shared-blind-spot risk?

**Reject ratio (order of magnitude)**. Exact counts were not
maintained, but qualitatively: many proof steps required multiple
operator iterations; some operations failed entirely (operator
`FAILED` states; rate-limit hits; Lean build regressions). The
honest order-of-magnitude summary is **$10^{2}$–$10^{3}$ rejected
or failed agent turns across the development**; the final proof
represents a small fraction of total LLM output. Typical
proof-engineering lemmas required 5–50 rejected attempts before an
accepted diff; difficult lemmas (e.g.,
`heckel_cochromatic_second_moment`) required >100.

**HIL review granularity**. The human supervisor reviewed:
- **at the theorem-statement level** for the four publishable
  theorems and the four paper-backed axiom statements (every change
  to these went through human read-through before commit);
- **at the lemma level** for supporting modules
  (`CrossingPartB.lean`, `CrossingWindowProof.lean`,
  `PartBAlphaMinusTwoFirstMomentAxiom.lean`,
  `PartBAlphaMinusTwoFirstMomentBridge.lean`,
  `CumulantAlphaMinusTwo.lean`,
  `GapArithmetic.lean`);
- **at the build-passes level** for the large legacy module
  `PartBProfileBridge.lean` (29512 lines): the human supervisor
  did not read every tactic; review was at the granularity of
  "does `lake build` still pass and does `#print axioms` still
  return the expected set". This is honestly weaker review and is
  one of the principal reasons that file was kept in the legacy
  chain rather than promoted to the publishable path.

**Cross-model auditing**. *Not used.* The `operator` framework's
codex-acp adapter layer supports driving a non-Anthropic critic
model (e.g., `OPERATOR_CODEX_ACP__MODEL='gpt-5.4'`). This would have
been a partial mitigation of the shared-blind-spot risk — a critic
trained on different data has different blind spots. It was not
used in this development; the codex-brain (`gpt-5.3-codex-spark`,
`effort=low`) served only as the *operator orchestrator's
action-selection brain*, not as an independent worker-quality
critic. The five `/swarm-red-team` sessions were all run by
`claude-opus-4-7[1m]`. This is the obvious win the pipeline did
not take, and is the principal residual methodological gap of the
round-2 disclosure.

**Decision**: Record reject ratio, HIL granularity, and the
non-use of cross-model auditing in ADRs so that an adversarial
reader cannot infer the worst case (rubber-stamping, zero
iterations, deliberate suppression of cross-model evidence).

**Rationale**: All three items were P1 findings of round-2 red-team.
None was previously stated in the package.
